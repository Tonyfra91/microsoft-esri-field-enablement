## Use explicit sharing status

Use only these status values:

| Sharing status                    | Handling                                                                                                        |
| --------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| Public                            | Link the current authoritative public source; check separate reuse rights before copying                        |
| Approved for external partner use | Verify explicit permission covers public GitHub listing; partner-only approval does not imply public permission |
| Validation required               | Keep the unapproved asset and private links out of the public inventory until status is confirmed               |
| Internal only - do not distribute | Never list, link, upload, or describe the internal resource in this public repository                           |

The last two values define handling rules, not an invitation to populate this
public catalog with internal or unvalidated assets. Use an approved private
system to track private approval work. Do not expose internal SharePoint URLs,
private meeting notes, customer details, unpublished product claims, or internal
Microsoft or Esri materials.

## Before adding a resource

Confirm audience, owner, date, current product scope, sharing approval, and the
public-safe destination. Follow the [source policy](source-policy.md) and
[visual asset rules](visual-assets.md). A source review date is not its
publication date or a product validation.

or return to the [seller front door](../README.md).
