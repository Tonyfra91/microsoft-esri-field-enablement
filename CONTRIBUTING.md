## Contributing

Contribute concise, public, source-backed resources that help field teams move
from a customer scenario to an informed evaluation. Avoid duplicating product
documentation or adding pages solely to fill folders.

## Public-content requirements

Do not submit Microsoft Confidential information, internal-only information,
private meeting details, unreleased roadmap information, non-public pricing,
credentials, personal or customer-sensitive data, or unsupported product claims.
These requirements apply to files, issues, pull requests, comments, and screenshots.

Only contribute material you have the right to publish. Link to third-party
documentation rather than copying it. Identify applicable licenses for demo data
and assets. Repository contributions are provided under the [MIT License](LICENSE);
linked third-party material retains its own terms.

## Evidence and editorial requirements

* Cite authoritative public Microsoft or Esri sources next to technical claims
* Record the source review date and any version or environment scope
* Separate documented capabilities from curated recommendations and hypotheses
* Use "Source to be validated" for pending evidence, not as permission to assert a fact
* Check limitations, availability, and licensing against current official sources
* Flag conflicting documentation for review instead of resolving it by assumption
* Use concise GitHub Markdown and relative links for repository navigation

## Contribution workflow

1. Open a public-safe issue or pull request describing the user need and proposed change.
2. Include sources, review dates, and unresolved validation questions.
3. Check relative links and confirm external links reach the intended official pages.
4. For demos or architectures, include prerequisites, test evidence, limitations,
   data rights, and cleanup instructions as applicable.
5. Request maintainer review before merge.

Reviewers should reject unsupported claims and sensitive content, not rewrite
them into implied commitments. If sensitive material is accidentally published,
do not repeat it in an issue; use an approved private reporting channel and
follow the applicable incident process.
