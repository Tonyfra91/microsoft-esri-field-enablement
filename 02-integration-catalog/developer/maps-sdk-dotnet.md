## In one sentence

ArcGIS Maps SDK for .NET is a developer starting point for building mapping
experiences into custom .NET applications.

## Conversation card

**30-second explanation:** When existing applications do not fit the user's
task, explore a custom mapping experience. Start with one required interaction
and check whether its value justifies development and ongoing maintenance.

**Do not promise:** A finished application, every platform or offline workflow,
or SDK licensing based on a developer persona in the diagram.

**Agree on a next step:** Have the application owner, .NET developer, and GIS
specialist identify one task, target platform, data access needs, and a small
prototype acceptance test. Use the
[technical checklist](../../05-architecture/technical-qualification.md).

## Why a customer cares

* Shape an application around a specific user task
* Consider geographic context within a purpose-built workflow
* Evaluate whether custom development is justified over an existing app

## Listen for this

> "Our users need a dedicated application."

> "An existing map app does not support this specific user interaction."

> "We need to understand who will maintain a custom application."

## Questions to ask

* What must a user do that existing applications do not support?
* Which devices, data, and access conditions matter?
* Who owns development, maintenance, and support?
